# Component rules

- Buttons use explicit verbs. Consequential controls show target and effect before approval.
- Inputs always have visible labels, inline errors, and stable geometry while validating.
- Tables use 36 to 44px rows, sticky headers, direct status, and responsive stacked rows.
- Dialogs trap focus, close with Escape, restore focus, and never hide the exact action.
- Toasts never cover approval or checkout actions.
- Charts include units, time range, labels, deploy markers, a text summary, and a table alternative.
- Agent activity shows tool, purpose, state, and time. It never exposes private reasoning.
- Approval cards show normalized action, target, evidence, expected effect, risk, expiry, and undo path.
- Store product tiles expose name, material, price, and stock without hover.
- Every third-party component must use project tokens and preserve its accessible behavior.
